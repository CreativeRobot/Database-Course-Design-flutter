# 图书两级分类与树形展示设计

## 目标

将现有 `category.parent_id` 自关联关系明确为两级图书分类：一级分类没有父级，二级分类归属于一个一级分类。后台以树形界面呈现并维护该关系；商城端支持一级分类和二级分类的级联筛选。

## 数据模型

不新增数据表。`category.parent_id` 保持外键引用 `category.id`：

- `parent_id IS NULL`：一级分类；
- `parent_id = 一级分类.id`：二级分类；
- 图书与分类仍通过 `book_category` 多对多关联。

服务层拒绝三级分类、把有子分类的分类下移到其他父分类、循环引用、自身为父分类，以及删除仍有子分类或已关联图书的分类。

## 接口与数据流

保留 `GET /api/categories` 的扁平列表，以兼容已有搜索数据加载。新增 `GET /api/categories/tree` 和 `GET /api/admin/categories/tree`，返回根分类及其 `children`。树接口用于管理端展示；编辑弹窗仍加载扁平列表，以便选择一级父分类。

当搜索传入一级分类 ID 时，后端将该 ID 与所有直属二级分类 ID 一同纳入图书分类匹配；传入二级分类 ID 时仅匹配该二级分类。

## 前端展示

管理端以可展开树列出分类：一级分类为文件夹节点，二级分类缩进显示。分类编辑弹窗只显示一级分类作为可选上级。

商城搜索页保留一个实际提交到 API 的 `categoryId`：一级下拉选择时提交一级 ID；二级下拉选择时提交二级 ID。状态由现有选中分类推导，因此不增加重复的筛选状态。

## 错误与验证

后端使用业务异常说明：父分类必须为一级分类、分类最多两级、存在子分类的分类不能下移。前端将后端错误通过既有错误提示展示。

新增后端单元测试覆盖两级层级约束、树构建和父级筛选的有效分类 ID；新增 Flutter 单元测试覆盖分类父级/子级解析与层级辅助逻辑。
